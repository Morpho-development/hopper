# Hopper

[English](README.md) | [Русский](README.ru.md)

Hopper — приватное self-hosted облако для хранения и передачи файлов между компьютерами и телефонами. В состав входят API на Go, React PWA, база SQLite, локальные Docker volumes и автоматический HTTPS через Caddy.

## Возможности

- Авторизация по логину, пароли хешируются через bcrypt
- Ротация HttpOnly, Secure, SameSite cookie и серверный выход из аккаунта
- Загрузка, скачивание, папки, переименование, безопасное превью и квоты
- Защищённая полная очистка хранилища с подтверждением
- Временные публичные ссылки со сроком действия и лимитом скачиваний
- Сообщения, синхронизируемые между устройствами
- Адаптивная устанавливаемая PWA
- Локальный Docker-режим и публичный режим с автоматическим HTTPS

## Требования

- Linux-сервер или компьютер с Docker Engine и Docker Compose v2
- Не менее 1 ГБ оперативной памяти и достаточно места под выбранную квоту
- Для публикации: публичный IPv4 и доступные TCP-порты `80` и `443`

## Быстрый Старт

```bash
git clone https://github.com/Morpho-development/hopper.git
cd hopper
cp .env.example .env
openssl rand -hex 48
```

Откройте `.env`, укажите сгенерированное значение в `JWT_ACCESS_SECRET`, задайте логин и надёжный пароль администратора длиной не менее 12 символов:

```env
JWT_ACCESS_SECRET=замените_на_сгенерированный_секрет
FIRST_RUN_ADMIN_LOGIN=admin
FIRST_RUN_ADMIN_PASSWORD=замените_на_длинный_случайный_пароль
```

Никогда не добавляйте `.env` в Git и не публикуйте его содержимое.

## Установка На Сервер С HTTPS

Направьте домен на IP сервера. Если домена нет, для адреса `203.0.113.10` можно бесплатно использовать hostname `203-0-113-10.sslip.io`.

Укажите в `.env`:

```env
APP_ENV=production
APP_DOMAIN=203-0-113-10.sslip.io
FRONTEND_BIND=127.0.0.1
```

Запустите Hopper:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Откройте `https://203-0-113-10.sslip.io`. Caddy автоматически получает и продлевает TLS-сертификат. Backend не публикуется на хосте, а порт `3000` остаётся доступен только через loopback.

## Локальная Установка

Оставьте в `.env` режим разработки и локальную привязку:

```env
APP_ENV=development
APP_DOMAIN=localhost
FRONTEND_BIND=127.0.0.1
```

Запустите контейнеры:

```bash
docker compose up -d --build
```

Откройте <http://localhost:3000>. Для доступа с доверенных устройств в одной локальной сети установите `FRONTEND_BIND=0.0.0.0` и ограничьте порт `3000` системным firewall. Не публикуйте этот HTTP-режим в интернете.

## Первый Вход

На пустой базе backend создаёт аккаунт из `FIRST_RUN_ADMIN_LOGIN` и `FIRST_RUN_ADMIN_PASSWORD`. После входа логин и пароль можно изменить в настройках аккаунта. Изменение этих переменных не сбрасывает существующий аккаунт.

Самостоятельная регистрация по умолчанию отключена:

```env
REGISTRATION_ENABLED=false
```

## Ограничение Хранилища

Лимиты задаются в байтах:

```env
# Общая квота: 100 ГиБ
INSTANCE_QUOTA_BYTES=107374182400

# Максимальный размер одного файла: 5 ГиБ
MAX_UPLOAD_BYTES=5368709120
```

Готовые значения:

| Объём | Байты |
| --- | ---: |
| 10 ГиБ | `10737418240` |
| 50 ГиБ | `53687091200` |
| 100 ГиБ | `107374182400` |
| 1 ТиБ | `1099511627776` |

Hopper показывает занятую и доступную квоту в интерфейсе. При этом на физическом диске сервера также должно быть достаточно свободного места.

## Основные Команды

```bash
# Состояние контейнеров
docker compose -f docker-compose.yml -f docker-compose.prod.yml ps

# Последние логи
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs --tail=100

# Остановка без удаления данных
docker compose -f docker-compose.yml -f docker-compose.prod.yml down
```

Не добавляйте `-v` к `docker compose down`: этот флаг удаляет базу и сохранённые файлы.

## Резервное Копирование И Обновление

Перед каждым обновлением создавайте копию обоих Docker volumes по инструкции [Backup and restore](docs/BACKUP.md). Затем выполните:

```bash
git pull --ff-only
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Миграции базы данных применяются автоматически при запуске backend.

## Безопасность

- Для публичной установки всегда используйте HTTPS.
- Не включайте регистрацию без необходимости.
- Используйте уникальный пароль администратора и по возможности SSH-ключи.
- Регулярно обновляйте ОС и Docker, храните зашифрованные резервные копии вне сервера.
- Любой получатель временной ссылки может скачать соответствующий файл до истечения срока или лимита скачиваний.

Правила сообщения об уязвимостях и границы защиты описаны в [SECURITY.md](SECURITY.md).
